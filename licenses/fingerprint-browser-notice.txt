The build inputs and hashes are recorded in
tools/fingerprint-browser/native-engine/source-manifest.json. Identity controls
are derived from public adryfish/fingerprint-chromium 148 patches at commit
13b89eae304123f0710f2d33fd0816a2f61d7ffc and ported to the pinned Chromium 150
source. MC Proxy's owned-Canvas patch adds private-buffer native readback and
Window/Worker Blob processing. The r2 repair uses position-independent full
low-bit projection and a shared observable projection for normalized float
channels. It removes the seed-only JavaScript device-memory value so Window,
Worker and HTTP Client Hints share Chromium's native approximated-memory source.
This is not a byte-for-byte rebuild of adryfish's
150 binary and does not imply publication or endorsement of this build by that
project. Source, complete component pins and bounded acceptance evidence:
docs/components/fingerprint-browser-150.md.

Protection is bounded. Repeated writeback, Float16 quantization and integer
translation-majority counterexamples have been checked on the r2 candidate and
again through the default production runtime reader. Production observation,
profile/migration, local STUN and isolated bundle installation also passed.

Chosen +1/-1 composite color transforms can still recover original pixel values;
they are explicitly recorded as unprotected, not accepted protection. The
component does not promise complete device replacement, anonymity, account
unlinkability or immunity from account bans.

This repair does not bring Chromium 150 up to the reviewed Windows stable
security baseline 155.0.8059.85. Advisory version checks and release-audit
blockers report the debt; they do not download or apply security patches.
The pinned ungoogled recipe also uses safe_browsing_mode=0 and no Google API
credentials, so Google Chrome Safe Browsing service equivalence is not provided.
Resource hashes and sandboxing do not replace upstream security maintenance.
Chrome remains the default browser.
